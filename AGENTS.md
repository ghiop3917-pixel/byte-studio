# Правила Byte Studio Lead Hunter

- Общайся с владельцем, составляй документацию и пользовательские сообщения на русском языке.
- Сохраняй действующий Telegram-мониторинг, авторизацию, сессию, источники и JSON-настройки.
- Не удаляй файлы, записи, историю и конфигурации без прямого разрешения владельца.
- Перед изменением SQLite создавай резервную копию через Backup API и проверяй её целостность. Миграции выполняй транзакционно, с номером версии и совместимостью со старыми данными.
- Все данные этапов 1 и 2 находятся в существующей базе monitor.sqlite3. Новые независимые базы требуют технического обоснования.
- Сохраняй оригиналы сообщений до фильтрации. Сеть выполняется вне транзакций сохранения.
- Сохраняй все 17 проверок этапа 1. После правок запускай связанные тесты.
- Проверяй владельца при каждом обращении к CRM. Контакты разных платформ не объединяй по похожему имени.
- Черновики отличаются от отправленных сообщений. Отправка потенциальным заказчикам требует отдельного подтверждения владельца.
- AI-оценки, бюджеты и цены оставляй пустыми при отсутствии данных. Отделяй фактическую выручку от прогнозов.
- Не используй платные API, не обходи ограничения платформ и не раскрывай секреты в коде, логах или документации.
- API этапа 2 доступен только через loopback. Публичное развёртывание, VPS и следующие крупные этапы требуют решения владельца.
- Срок хранения 30 дней пока используется только для отчёта. Автоматическое удаление выключено.
- Работай точечными изменениями, переиспользуй компоненты, экономь контекст и зависимости.

Архитектура, API и схема базы описаны в docs/.

## Продажи и веб-интерфейсы

- Коммерческие расчёты используют явно введённые часы, ставку и расходы; не выдавай их за рыночную оценку или бюджет клиента.
- Публичная форма создаёт заявку, контакт и уведомление одной транзакцией; сохраняй её идемпотентность, honeypot и ограничение частоты.
- Демо-проекты должны оставаться явно обозначенными; никогда не подменяй ими клиентские кейсы.
- Не публикуй корень проекта. Для сайта предназначен только web/studio. Публичный backend требует отдельного решения, HTTPS, авторизации и ограничения доступа.

## Контроль качества и обслуживание

- Считай полезность по последнему решению владельца, а кандидатов правил показывай отдельно. Малую выборку и неизвестную полноту обозначай явно.
- Поддержанное предложение не означает автоматически применённое правило. Направления, источники и фильтр без отдельного решения не изменяй.
- Служебные отчёты не рассылай в Telegram. Обслуживание не создаёт outbox-сообщений.
- Сохраняй ограниченные повторы, токены аренд и журнал выполнения. Не переотправляй ambiguous автоматически.
- Копии проверяй, но не удаляй старые и не восстанавливай поверх рабочей базы без разрешения.


## Компании из карт

- Компании из 2ГИС/Яндекс/Google — отдельные потенциальные клиенты, не входящие заказы.
- Не подменяй неизвестный сайт отсутствующим. В выдаче явно писать «сайт не указан в карточке».
- Telegram/MAX только опубликованные; не строить ссылки по номеру и не выдумывать описание.
- Соблюдать robots.txt, 403/429/капчи; без обхода, cookie-подмены, платных API и автообращений.
- Снимки и точные ID сохранять, похожие компании не сливать в CRM автоматически.
- Рабочая БД/сессия остаются без изменений до отдельного разрешения на миграцию.
