# Поиск фриланс-заказов в Telegram

## Качество заявок, этап 3

Добавлены намерения, объяснимая оценка правил, очередь «На проверку» и обратная связь. Черновики учитывают язык и задачу. Команды /reviews и /quality доступны получателю бота. Подробнее в [ANALYSIS.md](docs/ANALYSIS.md).

Внешний AI пока не подключён. Настройки направлений сохранены. Сомнительные сообщения можно одобрить вручную, оригиналы не удаляются.

## CRM-ядро, этап 2

CRM использует ту же monitor.sqlite3. Новые Telegram-лиды получают связанную карточку, клиента, источник, входящую запись и черновик в транзакции обработки. Сетевой отправки клиенту в CRM нет.

Локальный API запускается через `python crm_api.py` после задания CRM_API_TOKEN. Он слушает только 127.0.0.1. Настройка, маршруты, фильтры, экспорт и примеры приведены в [CRM API](docs/CRM_API.md). Схема описана в [DATABASE.md](docs/DATABASE.md), устройство компонентов — в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

Зависимости перечислены в requirements.txt. В текущем окружении Telethon и openpyxl уже установлены. Проверки запускаются через `python -m unittest discover -s tests -v`.

## Надёжное Telegram-ядро

Для работы с долговечными очередями используй `python monitor.py`. Подробности хранения оригиналов, восстановления, резервных копий и неоднозначной доставки описаны в [инструкции этапа 1](docs/RELIABILITY.md).

Статус очередей и heartbeat можно посмотреть через `python core_admin.py`. Сетевой тайм-аут доставки требует проверки чата перед ручным повтором. Автоматический повтор такой карточки отключён для защиты от дублей.

## Мониторинг через подключённый аккаунт

`python monitor.py --check` проверяет чтение настроенных групп по отдельности. Для постоянного мониторинга запусти `python monitor.py` с той же сессией Telegram. При запуске программа запросит API ID, API hash и токен бота. Перед запуском отправь своему боту `/start` с аккаунта получателя. Токен и API hash можно задать через переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_LEADS_API_HASH`, API ID через `TELEGRAM_LEADS_API_ID`.

Каждый источник планируется на повторную проверку через 20 секунд после успешного чтения. При ограничениях Telegram интервалы увеличиваются. Новый источник начинает с последних 100 сообщений. После перезапуска чтение продолжается с сохранённой позиции. Путь к файлу сессии можно передать через `--session`. Храни файл сессии как пароль. Запускай один экземпляр программы.

Бот читает новые сообщения из настроенного списка групп и супергрупп и присылает владельцу возможные заказы. Каналы и их публикации исключены. В карточке есть категории, источник, фрагмент сообщения и кнопка перехода к оригиналу, если Telegram поддерживает ссылку для этого чата.

Фильтр ищет запрос и подходящую тематику, включая ранние потребности в автоматизации. Направления выбираются в боте. Долговечный режим предотвращает дубли по ID группы и сообщения, CRM дополнительно учитывает владельца и платформу. Возможные дубли проверяются вручную. Старый прямой режим bot.py сохраняет прежнее подавление одинакового текста на 48 часов. Нестандартно сформулированные заказы могут пропускаться, а некоторые объявления требуют ручной оценки.

Мониторинг работает на Python 3.10+ с Telethon и SQLite. Обращений к ИИ нет. Оригиналы сообщений и метаданные сохраняются в базе до классификации. Очереди и история переживают перезапуск. Бот присылает карточки в личный чат получателя, а отклики заказчикам отправляешь ты.

## Первый запуск

1. Создай отдельного бота через [@BotFather](https://t.me/BotFather) и задай его токен в переменной окружения `TELEGRAM_BOT_TOKEN`. Храни токен в секретах сервера или передавай при запуске. Токен не нужен в исходниках и переписке.
2. В папке проекта выполни `python bot.py`. В личном чате с ботом отправь `/start` и получи свой ID. Останови процесс через Ctrl+C.
3. Укажи свой ID в `TELEGRAM_OWNER_ID` и запусти бота снова. Команда `/status` в личке покажет число настроенных источников.
4. Добавь бота в доступную группу с согласия администрации. В группе отправь `/source@имя_бота` со своего аккаунта. Бот пришлёт ID группы тебе в личку.
5. Задай `TELEGRAM_SOURCE_IDS` через запятую, например `-1001234567890,-1009876543210`, и перезапусти бота. Для проверки напиши в тестовой группе «Ищу исполнителя, нужен лендинг на Tilda».

Чтобы читать обычные сообщения группы, боту нужны права администратора или отключённый режим приватности через `/setprivacy` в BotFather. После изменения режима может понадобиться заново добавить бота в группу. Доступ к чужим чатам зависит от их администраций. [Правила получения сообщений Telegram](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)

На VPS запускай один экземпляр бота под обычным пользователем. Для автозапуска можно использовать systemd с перезапуском при сбое. Папка проекта должна быть доступна на запись этому пользователю для хранения `leads.sqlite3`. Вебхук у этого бота должен быть отключён, поскольку бот сам запрашивает новые сообщения.

## Локальная CRM-панель и сайт Byte Studio

Запусти `start-crm.cmd`. В окне появится случайный ключ входа. Сайт: http://127.0.0.1:8765/ . Панель: http://127.0.0.1:8765/crm . Telegram-мониторинг работает отдельно.

Доступны коммерческие предложения, вопросы, follow-up, расчёт цены по собственным данным и подсказки по ответам клиента. Веб-панель позволяет вести карточки, контакты, воронку, заметки, сделки и напоминания, проверять сообщения и экспортировать базу. Сайт содержит услуги, две интерактивные демонстрации и форму заявки в CRM. Никаких отправок клиентам автоматически.

Подробности, ограничения и публикация: [docs/WEB_AND_SALES.md](docs/WEB_AND_SALES.md). Сайт и API пока доступны только локально; Netlify и VPS не развёрнуты.

## Этап 7 — качество и обслуживание

В CRM появились «Качество источников», «Предложения» и «Обслуживание». Оценки доступны в карточках и Telegram; причины отказа сохраняются. Проверенные копии выполняются раз в сутки при включённом мониторинге. Служебных рассылок и автоматического изменения правил нет.

В боте: `/sourcesquality` и `/maintenance`, либо кнопки в «Качество». Подробности: docs/OPERATIONS.md.

Локальный запуск через start-crm.cmd выбирает свободный порт Windows. Адреса сайта/CRM и ключ входа показаны в его окне; используй фактически напечатанный адрес вместо фиксированного порта.


## Путь Telegram-сессии

`--session` у monitor.py, expand_sources.py и source_growth.py имеет приоритет.
Без аргумента используется `TELEGRAM_LEADS_SESSION`, затем путь платформы:
Windows — `%LOCALAPPDATA%/TelegramLeads/monitor.session`;
Linux/macOS — `${XDG_STATE_HOME:-~/.local/state}/telegram-leads/monitor.session`.
connect.py использует тот же путь. Существующую сессию перемещать автоматически не нужно:
при смене системы явно укажите её расположение через переменную окружения.


## Базы данных и локальная проверка

`leads.sqlite3` используется **только старым прямым режимом `python bot.py`**.
Основной режим `python monitor.py`, CRM, очереди и сайт используют единую `monitor.sqlite3`.
Новые рабочие базы не создаются; тесты используют только временные базы и FakeClient.

Инструменты разработки устанавливаются отдельно: `python -m pip install -r requirements-dev.txt`.
Проверка: `check.cmd` на Windows или `sh check.sh` на Linux/macOS.
Скрипт завершается с ошибкой при провале ruff, тестов или покрытия ниже 70%.
Браузерные smoke-тесты по умолчанию пропускаются: включите `RUN_BROWSER_SMOKE=1`,
если отдельно подготовлены Playwright и локальный браузер. Они не входят в runtime-зависимости.

`TRUSTED_PROXIES` (по умолчанию пусто) и `crm_api.py --trusted-proxies` принимают
IP/CIDR через запятую, например `127.0.0.1,10.0.0.0/8`. CLI имеет приоритет.
Только от доверенного peer принимается X-Forwarded-For: цепочка просматривается справа,
до первого недоверенного IP. Неверный заголовок игнорируется. Не добавляйте общедоступные
сети в доверенные. Это не включает публичное развёртывание и не меняет защиту Origin.
Лимит формы — пять попыток в час, включая отклонённые; точный повтор принятого request_id
возвращает прежнюю квитанцию и не расходует лимит. IP хранится только в виде хеша.
