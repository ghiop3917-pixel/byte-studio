## OneDrive: риск и план без выполнения

Проект находится внутри C:/Users/makar/OneDrive/Desktop/клод работа/фул.
Синхронизация SQLite и файлов -wal/-shm не атомарна, возможны конфликтующие копии,
задержки доступа и неполное восстановление. OneDrive не заменяет SQLite Backup API.

Безопасный будущий перенос (сейчас не выполнялся):

1. Согласовать окно остановки и завершить все пишущие процессы: мониторинг, API,
   расширение источников. Проверить отсутствие открытых соединений/работающих экземпляров.
2. Создать согласованную копию через SQLite Backup API, проверить integrity_check и
   foreign_key_check. Сохранить исходный проект и проверенную копию для отката.
3. Копировать, а не перемещать, в C:/Dev/byte-studio вне OneDrive. Для файлов после остановки
   сверить относительные имена, размеры и SHA-256 исходной и целевой копий.
   Хеш файла, созданного Backup API, сверять с его скопированным экземпляром,
   а не требовать совпадения с бинарным образом работающей SQLite.
4. Telegram-сессия уже вне проекта: сохранить её расположение и авторизацию.
   Не копировать секреты в Git; при необходимости явно задать путь окружением.
5. Подготовить окружение из requirements.txt/requirements-dev.txt, выполнить check и
   браузерные сценарии на временных БД. Проверить пути локальных запускателей.
6. Запустить один экземпляр в новом каталоге, проверить heartbeat, очереди и получение
   сообщений. Старый экземпляр одновременно не запускать.
7. Откат: остановить новый экземпляр. Если новых рабочих записей ещё нет — вернуть
   запуск из сохранённого старого каталога. Если записи появились — сначала сохранить их
   проверенной копией; обратное восстановление выполнять только отдельно согласованно,
   не перезаписывая старую базу автоматически.
