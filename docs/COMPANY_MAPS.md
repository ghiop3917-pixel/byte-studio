# Компании с неуказанным сайтом

## Назначение

Владелец выбрал Москву и Ярославль, компании по привозу автомобилей из Китая.
Это отдельная книга потенциальных клиентов в том же боте. Компания не считается
входящим заказом и не попадает в Telegram-outbox лидов. Никаких автоматических
обращений, холодных рассылок, генерации контактов по телефону или AI-описаний нет.

## Поля и отбор

Название, описание из карточки (либо опубликованная категория деятельности),
телефоны, адрес/город, опубликованные Telegram/MAX, ссылка на первичную карточку,
источник и время проверки. MAX распознаётся по max.ru; по номеру ссылки не строятся.
Пустые Telegram/MAX показываются как «не указано». Описание не дописывается из
поискового запроса. Для выдачи обязательны название, непустое описание и полный
телефон, подтверждённый город и признаки импорта авто из Китая в самой карточке.
Салон китайского бренда без признаков привоза не считается автоматически импортёром.

Есть три различных состояния: сайт указан, сайт не указан в разобранных контактах,
контакты неизвестны/недоступны. В выдачу идут только вторые; неизвестные не считаются
отсутствием сайта. Это не доказывает, что у компании нет сайта где-либо ещё.
Явные ссылки на собственный сайт исключают карточку; опубликованные Telegram/MAX/VK
не подменяются отдельным сайтом. Нераскрытый redirect вместо сайта не считается его
отсутствием. Рекомендованные соседние организации со страницы не принимаются за основную.

Точные дубли — provider + постоянный ID карты. Снимок меняется только при изменении
отобранных данных, прежние снимки сохраняются. Между картами совпадение имени,
города и основного телефона сворачивает повтор в выдаче и помечает возможный дубль,
но исходники не объединяются/не удаляются. Если у такой же компании на другом
источнике указан сайт, она исключается из выдачи. Это консервативная эвристика,
не доказательство идентичности юридических лиц; разные основные телефоны могут
оставить похожие карточки отдельно для ручной сверки.

## Доступ и запуск

Раздел «Компании без сайта» в главном меню владельца; команды `/companies` и
`/companies_scan`. В разделе — запуск, просмотр по пять карточек, CSV.
Каждое действие повторно проверяет зарегистрированную роль администратора и ban;
ID владельца не берётся из callback. Обычный подписчик не видит чужую книгу.
CSV выдаётся только по запросу владельца; опасные формулы экранируются.

Рабочая monitor.sqlite3 пока не мигрирована, поэтому новый интерфейс не запускался
в настоящем боте. Объявлены три новые lh_-таблицы в той же БД, без создания новой
базы и без применения DDL к рабочей SQLite. Нужна отдельная согласованная миграция
всего нового ядра с резервной копией и проверкой целостности.

После такой активации общий `python -m app.main --run` содержит coroutine companies,
без дополнительного фонового процесса. Для сетевого сбора нужны одновременно
COMPANY_MONITOR_ENABLED=true и ручное задание владельца. Автоматического ежедневного
пересканирования нет. COMPANY_RENDER_ENABLED=true разрешает необязательный браузер
для Google/JS-страниц: CHROME_PATH, затем PATH chrome/chromium/google-chrome/msedge,
затем стандартные пути Windows. Используется временный профиль, существующие
браузерные и Telegram-сессии не открываются и не изменяются. Только один браузер
за раз, ограничены время и объём. Браузерный режим по умолчанию выключен.

## Ограничения источников

- 2ГИС: публичная HTML-карточка и JSON.parse-состояние страницы, без исполнения
  встроенного JS, без внутренних ключей и скрытого API. Сайт проверяется по контактам.
- Яндекс: распознаётся CompanyMetaData из доступной страницы/полученного JSON.
  Живая проверка поиска вернула 403/капчу: источник приостанавливается. Автоматический
  сбор Яндекса в текущей среде не подтверждён; наличие адаптера не снимает блокировку.
- Google: публичная выдача и контактные DOM-поля карточки, при необходимости через
  Chrome. Неполные контакты не превращаются в «без сайта». Формат DOM может измениться;
  тогда карточка пропускается/задание приостанавливается, без вымышленных результатов.

Перед HTTP-чтением проверяется robots.txt, учитываются специфичный User-agent,
Allow/Disallow и wildcard/длина правила. Если robots недоступен или запрещает чтение,
сбор останавливается. Домены фиксированы, http/localhost/сторонние URL запрещены.
Прокси окружения, маскировка под другой аккаунт, решение капч, cookie-подмена,
логин и платные API не используются. Ссылки сайтов/TG/MAX не разыменовываются.

Повторы сетевых сбоев ограничены и имеют backoff; 429 задерживает все задания
источника с учётом Retry-After (секунды либо HTTP-date). 403/капча приостанавливают
источник, не блокируя остальные. Прогресс запроса/страницы/карточки и снимки
сохраняются. Повтор GET после сбоя безопасен: upsert и fingerprint не создают дубль.
Автоматических удалений, выхода из чатов и отправки предложений компаниям нет.

## Разовая проверка без рабочей базы

`python -m app.companies.cli` по умолчанию ничего не скачивает.
Явный пример: `python -m app.companies.cli --live --provider 2gis --city Москва --limit 3`.
Допустимы provider 2gis/yandex/google. `--output artifacts/companies-new.csv` пишет
только новый файл; существующий файл не перезаписывается. Папка должна существовать.
CLI не открывает monitor.sqlite3 и Telegram-сессию. Файл с контактами в Git не отправляется.

Реальная отдельная проверка (не часть тестов): 2ГИС, по три карточки Москвы и
Ярославля, все шесть с указанными сайтами, поэтому подходящих компаний 0.
Google: браузерная выдача дала четыре ссылки, одна карточка успешно разобрана,
сайт найден и она исключена. Яндекс: 403/капча. Это ограниченная проверка форматов,
не полный сбор рынков двух городов. Список компаний без сайтов не выдавался за собранный.

## Настройки

Полный перечень новых COMPANY_* есть в .env.example. По умолчанию: сбор и браузер
выключены; интервал 5 секунд, тайм-аут 30 секунд, страница до 4 MB, до двух страниц
и 20 ссылок на запрос, до трёх повторов, пять карточек в выдаче и до 1000 в CSV.
Существующие directions.json и business-sources.json не менялись. Зависимости не добавлены.

Официальная схема контактов 2ГИС: https://docs.2gis.com/en/api/search/places/examples/additional
Формат CompanyMetaData: https://yandex.ru/maps-api/docs/geosearch-api/response.html
Публичный пример ссылки MAX: https://dev.max.ru/help/miniapp-main
Эти ссылки поясняют форматы, но не означают подключение или оплату API.


## Обновление: произвольный город и сфера

Город и сфера теперь вводятся владельцем в боте: «Найти компании» → город → сфера.
Можно также `/companies_scan Казань | стоматологии`. Списка разрешённых городов
или отраслей нет. Исходные Москва/Ярославль и авто из Китая остались только
совместимыми настройками по умолчанию для старого вызова enqueue(actor).

Параметры и результаты каждого поиска хранятся отдельно по владельцу/городу/сфере.
Есть последние поиски, кэш на 15 минут, принудительное обновление и CSV выбранного
поиска. Первая найденная карточка может показываться в ответе без дополнительного
запроса (ожидание до 10 секунд), затем доступен просмотр пополняющегося результата.
Очередь пробуждается сразу, разные источники читаются параллельно; интервал
сохранён отдельно для каждого домена (по умолчанию 2 секунды). Скорость результата
не гарантируется: сайты компаний отсекаются, 403/капчи/429 не обходятся.

Google/Яндекс ищут город вместе со сферой; 2ГИС использует известный алиас или
транслитерацию названия. Не все города покрываются каждым источником: недоступный
город/источник даёт ошибку, а не подменяется другим городом. Сфера проверяется
по словам/корням опубликованного названия и описания, без новых AI-вызовов.
Это эвристика, не семантическая гарантия для любой формулировки.

В моделях CompanyScan добавлены niche/queries/requested_at и уникальность
(provider,city,niche,requested_by), CompanySearchResult связывает поиск с карточками.
Рабочая SQLite не мигрировалась. Для будущей миграции сохранить старые задания
с niche='' и queries='[]'; изменение уникальности выполнить без потери строк.
Раздел в настоящем боте по-прежнему требует согласованной миграции/активации.
